In the initial version (v1.0.0), I provided the game design structure to chatGPT o1-preview. Below is my prompt:
```
I want to create a shooting game using HTML, CSS, and JavaScript. Please write the respective code in game.html, styles.css, and control.js.
This game is a simple straight-track game where players control a car to move left and right, dodging obstacles to accumulate points.

- In the game, the car's speed is controlled by the program, and it will increase as the score gets higher.
- Scoring rules: every time you dodge or destroy an obstacle, you get 10 points.
- For every 100 points scored, the speed will increase.
- After 500 points, the frequency of obstacles will increase, and this frequency will increase for every subsequent 500 points.
- The basic obstacles should be designed as green. Additionally, after 500 points, red obstacles will appear that fire bullets in straight lines and at 45-degree angles. If hit by a bullet, the game ends.
- The controls are simple: use the left and right arrow keys to steer and the spacebar to fire bullets when a power-up is collected.
- There are two types of power-ups that appear randomly in the game, and you collect them by moving into position.
- Power-up 1: When collected, pressing the spacebar will fire a straight-line bullet that can destroy obstacles. This power-up lasts for 10 seconds, after which it disappears. The car will flash for the last 3 seconds before the power-up expires. Use a yellow-filled square to represent this power-up.
- Power-up 2: This power-up appears 20% as often as the first one. When collected, pressing the spacebar will fire bullets in a straight line and at 45-degree angles, allowing the player to clear obstacles. This power-up lasts for 8 seconds, and the car flashes for the last 3 seconds before it expires. Represent this power-up with a golden-filled circle that has a glowing effect.
- Power-ups will not overlap with obstacles.
- The game interface should display a box at the top showing the highest score (stored for future sessions) with the current score displayed directly below.
- There should be a clearly defined game area outlined with black lines.
- When the game ends, the page should prompt the player to choose whether to restart (not as a pop-up). Clicking "Yes" restarts the game, while clicking "No" will close the game.html page.
```

During this project, I realized the power of chatGPT, but also encountered several limitations. Below are some personal reflections on the process, which are not absolute.
* When providing information to chatGPT, it helps to organize the requirements by different aspects of the project (e.g., interface design, game logic) and list them clearly.
* Iterative prompts allowed chatGPT to provide feedback, which ultimately led to improved functionality and enhanced the fun factor of the game.
* I previously used chatGPT 4o, but found that it couldn't process a lot of information at once. Building up from simple features step-by-step seemed to be a better approach for 4o. However, chatGPT o1-preview could "digest" more information at once, making it easier to get the game structure right in one go.
* chatGPT's debugging capabilities seem somewhat limited, often leading to "circular reasoning." Breaking down the problems or having basic knowledge as a user becomes important. I wasn't very familiar with front-end syntax, but through this project, I gradually learned some syntax and referenced it in my prompts to enhance the precision of responses.
* Differences in chatGPT's text understanding: In my prompt, using "car" instead of "spaceship" seemed to produce different outcomes, with "car" yielding better results for understanding the overall game logic (though I'm not entirely sure if this really made a difference).
